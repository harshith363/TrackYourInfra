# Contributing to TrackYourInfra

Data contributors use the [GitHub Issue Forms](https://github.com/harshith363/TrackYourInfra/issues/new/choose). You do **not** need to edit code or JSON, fork the repository, or open or merge a pull request. Choose **New metro project**, **Project update**, **Source addition or correction**, or **Map correction**. Website bugs use the separate bug form and require developer work.

Submit one focused, public-source-backed change per issue. Identify an existing project by its ID (the last segment of its project URL). Give the exact public source URL, title, publisher, date when known, and explain what the source establishes for this project's scope. Do not include private contact information. If a city or agency is not yet supported, say so in the issue; the bot will give an actionable error rather than guess a location or require you to edit files.

For a route, open `/contribute/map/` on the running site to place dots and export GeoJSON, then paste it into the **Map correction** form. Only grant CC BY 4.0 permission if you created the submitted points and have the right to license them. A community route can be published as a dashed **unverified proposal** after review; this is not an accepted or surveyed alignment. An evidence-reviewed alignment needs a source establishing the exact geometry, not just the existence of the line.

The automated workflow generates a data-only pull request and checks the schema, references, values, geometry, and real-data site build. Passing automated checks does **not** verify factual truth. A maintainer opens the cited evidence and reviews the exact PR commit. Approval triggers another validation and an automatic merge. If the issue is edited, the earlier approval becomes stale and the bot generates a new reviewable revision. The issue and PR preserve the public record of the decision. The merged data appears after the next production deployment; a local server is not automatically synchronized with GitHub.

See [the automated contribution design](docs/automated-contributions-spec.md) and [review guide](docs/review-guide.md) for the verification rules. Code contributions remain possible through developer PRs, but are not part of the public data workflow.
