# Monitoring community contributions

There is no mandatory maintainer approval for data Issue Forms. Passing submissions are committed automatically to the separate `public-data` branch after structural checks and a real-data build. The issue, source URL, Git commit, and change-history record provide an audit trail, **not** an evidence-review certificate. `main` remains protected by code review.

Maintainers may periodically inspect newly published records. If a source does not support a claim, submit a correction issue or revert the specific data change; do not silently edit history. Community-drawn routes remain dashed, unverified proposals. Accepted alignments are not available through the automatic map form because coordinate checks cannot establish geographic accuracy.

Code pull requests and the `site` check remain. Production deployment is separate; a data commit does not update an already-running local checkout.
